# سایت یونیک طاها

تمام فایل‌های این پروژه عمداً در همین پوشهٔ اصلی قرار دارند. برای اجرای سایت یا انتشار آن، پوشهٔ دیگری نسازید و فایل‌ها را به زیرپوشه منتقل نکنید.

## انتشار سایت

`index.html` صفحهٔ اصلی سایت است. فایل‌های همراه آن، از جمله `logo.png`، `favicon.ico`، `og.jpg`، `site.webmanifest`، `robots.txt` و `sitemap.xml` را نیز در کنار آن نگه دارید. برای GitHub Pages، همین پوشه را به‌عنوان ریشهٔ سایت منتشر کنید؛ `CNAME` نیز باید در ریشهٔ منتشرشده بماند و دامنه در تنظیمات Pages فعال باشد.

اگر دامنهٔ اصلی یا `www` پاسخ 404 داد، در بخش تنظیمات Pages بررسی کنید آخرین انتشار موفق بوده و منبع انتشار همان ریشهٔ پروژه است. سپس دامنهٔ سفارشی ثبت‌شده در Pages و DNS آن را با `CNAME` تطبیق دهید. خطای 404 هاست با ویرایش HTML یا فایل‌های محلی برطرف نمی‌شود.

## وضعیت لایو آپارات

صفحه به‌ترتیب این منابع را بررسی می‌کند:

1. Cloudflare Worker تنظیم‌شده در `index.html`.
2. API عمومی آپارات از مرورگر بازدیدکننده.
3. فایل هم‌مکان `live-status.json`، فقط وقتی زمان آن حداکثر ۴۵ دقیقه قدیمی باشد.

در صورت خطا یا قدیمی بودن پاسخ، سایت «نامشخص» نشان می‌دهد و وضعیت را اشتباهاً آفلاین اعلام نمی‌کند. فایل فعلی `live-status.json` نمونه‌ای قدیمی است؛ تا وقتی منبع معتبری آن را به‌روزرسانی نکند، برای اعلام وضعیت زنده معتبر نیست.

### استقرار Worker

پیکربندی و کد Worker در `wrangler.toml` و `live-status-worker.js` کنار سایر فایل‌ها هستند. از همین پوشه اجرا کنید:

```powershell
npx.cmd wrangler login
npx.cmd wrangler deploy --config .\wrangler.toml
```

پس از استقرار، آدرس `/live-status` در نشانی `workers.dev` را آزمایش کنید. راهنمای مرحله‌به‌مرحله در `LIVE-STATUS-SETUP.md` است.

### گزینه‌های جایگزین

- `live-status.php` برای میزبانی روی هاستی که بتواند به آپارات وصل شود.
- `live-status-server.mjs` برای سرور Node.js 18 یا جدیدتر.
- `update_live_status.py` برای به‌روزرسانی فایل وضعیت محلی.
- `push_live_status.py` و `run.bat` برای ارسال وضعیت از رایانه‌ای که به آپارات دسترسی دارد به GitHub. ابتدا مقادیر نمونه را تنظیم کنید و توکن واقعی را در فایل عمومی یا مخزن قرار ندهید.

تنها استثنای پوشه‌بندی، فایل workflow فعال GitHub Actions در `.github/workflows/live-status.yml` است؛ GitHub فایل‌های workflow را فقط از همین مسیر می‌خواند. این workflow هر ۵ دقیقه وضعیت را از Cloudflare Worker می‌گیرد و فقط هنگام تغییر وضعیت یا قدیمی‌شدن فایل، `live-status.json` را به‌روزرسانی و commit می‌کند. اجرای زمان‌بندی‌شده ممکن است پس از فعال‌سازی GitHub Actions و انتشار workflow کمی زمان ببرد؛ اجرای دستی نیز از زبانهٔ Actions در GitHub ممکن است.

## بررسی سریع

- فایل‌ها را در همین پوشه نگه دارید؛ هیچ زیرپوشه‌ای برای اجرای سایت لازم نیست.
- `CNAME` دامنهٔ سفارشی GitHub Pages را مشخص می‌کند.
- `INDEXNOW-README.txt` راهنمای ارسال نشانی سایت به IndexNow است.
- در صورت قدیمی بودن API آپارات، پاسخ باید نامشخص بماند؛ وضعیت ساختگی در `live-status.json` ننویسید.
